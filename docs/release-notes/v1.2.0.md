# FrpcDeck v1.2.0

本版本把批量端口从“模板模式”改成了统一的可视化代理模型。普通代理、批量代理、导入和导出现在共用同一套结构化配置。

![批量代理列表](https://raw.githubusercontent.com/Luqijian/FrpcDeck/main/docs/screenshots/batch-proxies.png)

## 新特性

- `parseNumberRangePair` 块导入后，每个块显示为一个**可编辑的批量代理**，不再展开成多行。
- 代理编辑器新增「批量端口」开关，可配置：
  - 本地端口范围
  - 远程端口范围
  - 名称模板（`{localPort}` / `{remotePort}`）
  - 该批次共用的传输、健康检查等选项
- 新建 TCP/UDP 代理时可以直接创建批量代理。
- 导出 TOML 时自动重新生成 `range` + `parseNumberRangePair` 块。
- 代理列表、首页计数和状态都按“一个批量条目”统计；运行状态按该批次所有生成代理聚合。
- 所有普通代理类型（HTTP、HTTPS、STCP、XTCP、TCPMUX 等）仍然可以直接编辑。

## 行为变化

- 移除了单独的模板模式和只读模板代理视图。
- 旧版 `rawTemplate` 配置启动时会尝试迁移为批量代理；无法转换时会给出提示。
- 目前只识别 `parseNumberRangePair` 端口范围模板；任意 `if` / 自定义函数模板会被拒绝。

## 镜像

```text
ghcr.io/luqijian/frpcdeck:latest
ghcr.io/luqijian/frpcdeck:1.2.0
ghcr.io/luqijian/frpcdeck:v1.2.0
```

支持 `linux/amd64` 与 `linux/arm64`。

## 升级

```bash
git pull
docker compose pull
docker compose up -d
```

如果使用固定版本，把 `.env` 中的 `IMAGE_TAG` 改为 `1.2.0`。

完整变更见 [CHANGELOG](https://github.com/Luqijian/FrpcDeck/blob/main/CHANGELOG.md)。
